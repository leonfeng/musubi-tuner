# Krea 2 Style LoRA — Training Runbook (MSI EdgeXpert / GB10)

Local runbook for training Greg Rutkowski–style LoRAs with musubi-tuner on **MSI EdgeXpert (NVIDIA GB10, 128 GB unified memory, CUDA 13.0)**. Configs live in `configs/`; this document captures workflow, pitfalls, and fixes discovered during setup.

## Quick start

```bash
# 1. Place images + captions in dataset/
# 2. Cache latents and text-encoder outputs (once per dataset/caption change)
python src/musubi_tuner/krea2_cache_latents.py \
  --dataset_config configs/krea2.toml \
  --vae models/qwen_image_vae.safetensors

python src/musubi_tuner/krea2_cache_text_encoder_outputs.py \
  --dataset_config configs/krea2.toml \
  --text_encoder models/qwen3vl_4b_bf16.safetensors \
  --batch_size 1

# 3. Train
./train_krea2_lora.sh

# 4. Monitor loss (separate terminal)
tensorboard --logdir logs --bind_all
```

## Required model files

| File | Role |
|------|------|
| `models/raw.safetensors` | DiT for **training** |
| `models/turbo.safetensors` | DiT for **inference** (ComfyUI / `krea2_generate_image.py`) |
| `models/qwen_image_vae.safetensors` | VAE (latent cache + decode) |
| `models/qwen3vl_4b_bf16.safetensors` | Text encoder (caption cache only; not needed during train-only runs) |

**Workflow:** train LoRA on **RAW**, run inference on **Turbo** with CFG off (~8 steps).

## Config files

| File | Purpose |
|------|---------|
| `configs/krea2.toml` | Dataset: paths, resolution, `num_repeats`, `batch_size` |
| `configs/krea2_train.toml` | Training: LR, epochs, fp8, flash_attn, compile, logging |
| `train_krea2_lora.sh` | Launcher with unified-memory env vars |

### Current defaults (style training)

**Dataset (`configs/krea2.toml`):**

- **Single 1024px bucket** — flat `dataset/` layout, `cache/`
- **`num_repeats = 4`**, **`batch_size = 2`**
- `enable_bucket = true`, `bucket_no_upscale = false`

**Training (`configs/krea2_train.toml`):**

- **`network_dim = 32`**, **`network_alpha = 32`** — Krea authors' full-DiT default (264 Linear layers)
- **`timestep_sampling = "shift"`** + **`discrete_flow_shift = 2.5`** — correct for fixed 1024px (use `krea2_shift` only for mixed-resolution buckets)
- **`fp8_base` + `fp8_scaled`** (both required for K2)
- **`gradient_checkpointing = false`** — speed-first at 1024px; see [Memory / OOM](#memory--oom-gb10)
- **`flash_attn = true`** (not `sdpa`) — requires FlashAttention install; see below
- **`cuda_allow_tf32 = true`** — faster matmuls on GB10
- **`compile = true`** — recommended; first epoch is slower while kernels compile
- **`save_state = true`** for resumable runs
- **TensorBoard** → `logs/greg_rutkowski_<timestamp>/`
- **Checkpoints** → `output/` (not the same as logs)

### Training profiles

| Profile | `batch_size` | `gradient_checkpointing` | Steps/epoch (153 imgs × 4 repeats) | Notes |
|---------|--------------|--------------------------|-------------------------------------|-------|
| **Speed-first** | 1 | false | 612 | Fastest per step; used for initial v5 run (~50 min/epoch after compile warmup) |
| **Throughput-first** (current) | 2 | false | 306 | Fewer steps; watch memory on wide aspect-ratio images |
| **Memory-safe** | 1–2 | true | 612 / 306 | If OOM with batch 2 or when enabling sample generation |

## FlashAttention on GB10 (aarch64)

Prebuilt PyPI wheels and community wheels built for **torch 2.12** fail on this environment (**torch 2.14 dev + cu130**) with ABI/symbol errors. Build from source instead:

```bash
uv pip install ninja packaging setuptools wheel
CUDA_HOME=/usr/local/cuda TORCH_CUDA_ARCH_LIST=12.0 MAX_JOBS=2 \
  uv pip install flash-attn==2.8.3 --no-build-isolation
```

- **`TORCH_CUDA_ARCH_LIST=12.0`** — GB10 is sm_121; target sm_120 and rely on forward compatibility
- **`MAX_JOBS=2`** — conservative; build takes ~60 min on ARM Grace CPU but avoids system freeze
- Verify: `python -c "from flash_attn import flash_attn_func; print('OK')"`

Build notes are also in `pyproject.toml` under the optional `flash-attn` extra. Prebuilt aarch64 wheels may work if your torch version matches exactly.

After install, set **`flash_attn = true`** in `[training]` and remove **`sdpa = true`** (they are mutually exclusive).

## Dataset layout

Flat layout (current):

```
dataset/
  image_00000.png
  image_00000.txt
  ...
cache/          # generated by cache scripts
```

Each image needs a sidecar caption: same basename, `.txt` extension.

Wide images (e.g. 1920×1072) still bucket to 1024px max side but pack **many tokens** per sample — this affects memory more than square 1024×1024 images.

To sort a flat folder into resolution tiers (optional, legacy): `sort_krea2_dataset.py`. For style LoRAs on ~150 images, **single 1024 bucket is preferred** over multi-tier (896/1024/1280/1536).

After changing images, layout, or captions:

- **Latents:** re-run `krea2_cache_latents.py` if images or bucket resolution changed
- **Text encoder:** re-run `krea2_cache_text_encoder_outputs.py` if captions changed

## Captions (critical for style LoRAs)

Long VLM prose (~200–300 words, scene-heavy) tends to teach **subjects**, not **look**. Use short, consistent captions.

**Recommended structure:**

```
{trigger}, {medium}, {style/mood}, {palette/lighting}, {brief subject}
```

**Example (custom trigger):**

```
grgw style, digital fantasy painting, painterly brushwork, atmospheric perspective, dramatic cloudy sky, muted earth tones, golden rim light, armored angel with sword
```

**Example (artist name as trigger, for ComfyUI):**

```
painting by Greg Rutkowski, fantasy digital art, atmospheric lighting, painterly rendering, muted palette, golden highlights, lone knight on cliff
```

Rules:

- **25–45 words** max; same trigger on every image
- Emphasize medium, brushwork, atmosphere, palette — not plot
- Avoid "This image depicts…", object inventories, camera jargon
- Use the **same trigger at inference** as in training captions

Caption with vLLM/Gemma (`bulk_caption_generic.py` in `~/ai-workspace/utils/`): set `--max-tokens 96`, sync `.txt` files into `dataset/`, then re-cache TE outputs only.

## Training

```bash
./train_krea2_lora.sh
```

**Steps per epoch** = `(num_images × num_repeats) / batch_size`.

With 153 images, `num_repeats = 4`:

| `batch_size` | Steps/epoch |
|--------------|-------------|
| 1 | 612 |
| 2 | 306 |

**Observed speed (v5 run, batch 1, SDPA, compile + fp8, GC off):**

- Epoch 1: ~50 min wall clock; tqdm may show ~4.9 s/it (includes compile warmup across 28 DiT blocks)
- Epoch 2+: step counter advances noticeably faster than the smoothed s/it label — actual per-step time drops once kernels are cached

**Do not use for training:**

- `--sage_attn` / SageAttention3 (blocked by musubi-tuner for training)
- `discrete_flow_shift` together with `krea2_shift` (ignored in krea2_shift mode; use one or the other)

**Optional tuning:**

- `compile = true` — recommended on GB10 after first-epoch warmup cost
- `split_attn = false` — fine at 1024 single bucket
- `save_precision = "bf16"` — halve checkpoint size on disk (default save is fp32); see [Checkpoint size](#checkpoint-size)

## Memory / OOM (GB10)

Unified memory (CPU + GPU share one pool) means OOM can freeze the whole system — avoid aggressive memory probes during tuning.

**What uses memory:**

- DiT **weights** — mitigated by `fp8_base` + `fp8_scaled`
- **Activations** — scale with `batch_size × tokens_per_image`; wide bucketed images are expensive
- **`compile = true`** — extra transient memory during epoch-1 kernel build
- **`gradient_checkpointing`** — trades ~20–40% step speed for much lower activation memory

**Observed limits:**

- `batch_size = 8`, `gradient_checkpointing = false` → OOM (~115 GB used) even at 1024px only
- `batch_size = 1`, `gradient_checkpointing = false`, fp8 → stable for full 8-epoch v5 run

**If OOM, try in order:**

1. Set `batch_size = 1` in `configs/krea2.toml`
2. Set `gradient_checkpointing = true` in `configs/krea2_train.toml`
3. Set `compile = false` (lower peak during warmup)
4. Add `blocks_to_swap = 8` and `block_swap_h2d_only = true` under `[training]`
5. Keep sample generation disabled (`text_encoder`, `turbo_dit`, `sample_prompts` commented out)

Launcher env vars (in `train_krea2_lora.sh`):

- `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`
- `MALLOC_ARENA_MAX=2`
- `max_data_loader_n_workers = 1`, `persistent_data_loader_workers = false`

## Checkpoints and resume

Two artifacts are written each epoch:

| Artifact | Path | Purpose |
|----------|------|---------|
| LoRA weights | `output/{name}-00000N.safetensors` | Inference, ComfyUI |
| Resumable state | `output/{name}-00000N-state/` | Optimizer, scheduler, RNG |
| Final (train end) | `output/{name}.safetensors`, `output/{name}-state/` | Last epoch only |

`save_last_n_epochs_state = 2` keeps only the two newest `-state/` dirs.

### Checkpoint size

Default K2 LoRA in musubi-tuner targets **all 264 Linear layers** at **rank 32**, saved as **fp32** unless overridden:

| Config | Approx. size |
|--------|--------------|
| Rank 32, all 264 layers, fp32 (default save) | **~448 MB** |
| Rank 32, all 264 layers, bf16 | **~224 MB** |
| Rank 16, all layers, fp32 | ~224 MB |
| Rank 32, attention-only (140 layers), fp32 | ~237 MB |

Most ~224 MB LoRAs on Civitai use rank 16, attention-only subsets, and/or fp16/bf16 saves — not a different format.

To save bf16 in future runs:

```toml
save_precision = "bf16"
```

To convert an existing checkpoint:

```python
from safetensors.torch import load_file, save_file
import torch

src = "output/greg_rutkowski_v5_krea2.safetensors"
tensors = {k: v.to(torch.bfloat16) if v.is_floating_point() else v
           for k, v in load_file(src, device="cpu").items()}
save_file(tensors, src)
```

A fp32 backup was kept at `output/greg_rutkowski_v5_krea2.fp32.safetensors` when converting the v5 final checkpoint.

### How to stop

Wait for an epoch to finish (log shows `saving checkpoint` and `saving state at epoch N`), then Ctrl+C. Mid-epoch stop → resume from the **previous** epoch's `-state` dir.

### How to resume (same batch size / settings)

When resuming with **`resume`**, set `max_train_epochs` to the **cumulative total** you want (e.g. finished 8, want 4 more → `max_train_epochs = 12`):

```toml
max_train_epochs = 12
resume = "output/greg_rutkowski_v5_krea2-state"
```

Look for startup log:

```
resume training from local state: output/greg_rutkowski_v5_krea2-state
Loading states from ...
```

### Weights-only continue (settings changed)

Use when **`batch_size`**, attention backend, or other dataloader-affecting settings changed — optimizer/scheduler state from the old run will not align.

```toml
network_weights = "output/greg_rutkowski_v5_krea2.safetensors"
max_train_epochs = 4
output_name = "greg_rutkowski_v5b_krea2"
# no resume line
```

This is how the **v5b continuation run** is configured: 4 more epochs from the finished v5 LoRA with `batch_size = 2`, `flash_attn`, and `cuda_allow_tf32`.

```toml
logging_dir = "logs"
log_with = "tensorboard"
log_prefix = "greg_rutkowski_"
```

```bash
tensorboard --logdir logs --bind_all
```

Open http://localhost:6006. Metrics: `loss/current`, `loss/average`, `loss/epoch`, `lr/unet`.

Logs are **not** in `output/` — only checkpoints go there. The `logs/` directory is gitignored.

## Inference

### musubi-tuner CLI (Turbo)

```bash
python src/musubi_tuner/krea2_generate_image.py \
  "painting by Greg Rutkowski, armored angel in stormy clouds" \
  --dit models/turbo.safetensors \
  --vae models/qwen_image_vae.safetensors \
  --text_encoder models/qwen3vl_4b_bf16.safetensors \
  --lora_weight output/greg_rutkowski_v5_krea2.safetensors \
  --lora_multiplier 1.0 \
  --steps 8 --guidance_scale 1 \
  --width 1024 --height 1024 \
  --attn_mode torch \
  --save_path output/samples
```

Use the **same trigger phrasing** as in training captions. Try `--lora_multiplier` 0.8–1.2. Compare epoch checkpoints (`-000004`, `-000007`, etc.); evaluate multiple epochs — the final `output/{name}.safetensors` is not always the best.

### ComfyUI

Train on RAW, infer on **Krea 2 Turbo**, CFG off, ~8 steps. Match training trigger in prompts.

## Style training checklist

- [ ] Short captions, fixed trigger, 25–45 words
- [ ] Re-cache TE outputs after caption changes
- [ ] Single 1024 bucket, `num_repeats = 4`
- [ ] FlashAttention built for GB10 if using `flash_attn = true`
- [ ] 8–12 epochs; inspect loss curve in TensorBoard
- [ ] Evaluate multiple epoch checkpoints on Turbo (not only final `.safetensors`)
- [ ] If style is weak: shorten captions further, try `learning_rate = 5e-5`, or increase epochs
- [ ] Optional: `save_precision = "bf16"` or convert checkpoints before publishing (~224 MB)
