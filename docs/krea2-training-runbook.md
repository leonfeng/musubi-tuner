# Krea 2 Style LoRA — Training Runbook (DGX Spark)

Local runbook for training Greg Rutkowski–style LoRAs with musubi-tuner on **NVIDIA DGX Spark (GB10, 128 GB unified memory)**. Configs live in `configs/`; this document captures workflow, pitfalls, and fixes discovered during setup.

## Quick start

```bash
# 1. Place images + captions in dataset/
# 2. Cache latents and text-encoder outputs (once per dataset/caption change)
python src/musubi_tuner/krea2_cache_latents.py \
  --dataset_config configs/krea2.toml \
  --vae models/qwen_image_vae.safetensors

python src/musubi_tuner/krea2_cache_text_encoder_outputs.py \
  --dataset_config configs/krea2.toml \
  --text_encoder models/qwen3vl_4b_bf16.safetensors \
  --batch_size 1

# 3. Train
./train_krea2_lora.sh

# 4. Monitor loss (separate terminal)
tensorboard --logdir logs --bind_all
```

## Required model files

| File | Role |
|------|------|
| `models/raw.safetensors` | DiT for **training** |
| `models/turbo.safetensors` | DiT for **inference** (ComfyUI / `krea2_generate_image.py`) |
| `models/qwen_image_vae.safetensors` | VAE (latent cache + decode) |
| `models/qwen3vl_4b_bf16.safetensors` | Text encoder (caption cache only; not needed during train-only runs) |

**Workflow:** train LoRA on **RAW**, run inference on **Turbo** with CFG off (~8 steps).

## Config files

| File | Purpose |
|------|---------|
| `configs/krea2.toml` | Dataset: paths, resolution, `num_repeats`, bucket settings |
| `configs/krea2_train.toml` | Training: LR, epochs, fp8, compile, logging, resume |
| `train_krea2_lora.sh` | Launcher with DGX Spark env vars |

Current defaults (style training):

- **Single 1024px bucket** (`dataset/` flat layout, `cache/`)
- **`num_repeats = 4`**, **`batch_size = 1`**
- **`timestep_sampling = "krea2_shift"`** (do not set `discrete_flow_shift`; it is ignored in this mode)
- **`fp8_base` + `fp8_scaled`**, **`gradient_checkpointing`**, **`compile = true`**
- **`save_state = true`** for resumable runs
- **TensorBoard** → `logs/greg_rutkowski_<timestamp>/`
- **Checkpoints** → `output/` (not the same as logs)

## Dataset layout

Flat layout (current):

```
dataset/
  image_00000.png
  image_00000.txt
  ...
cache/          # generated by cache scripts
```

Each image needs a sidecar caption: same basename, `.txt` extension.

To sort a flat folder into resolution tiers (optional, legacy): `sort_krea2_dataset.py`. For style LoRAs on ~150 images, **single 1024 bucket is preferred** over multi-tier (896/1024/1280/1536).

After changing images, layout, or captions:

- **Latents:** re-run `krea2_cache_latents.py` if images or bucket resolution changed
- **Text encoder:** re-run `krea2_cache_text_encoder_outputs.py` if captions changed

## Captions (critical for style LoRAs)

Long VLM prose (~200–300 words, scene-heavy) tends to teach **subjects**, not **look**. Use short, consistent captions.

**Recommended structure:**

```
{trigger}, {medium}, {style/mood}, {palette/lighting}, {brief subject}
```

**Example (custom trigger):**

```
grgw style, digital fantasy painting, painterly brushwork, atmospheric perspective, dramatic cloudy sky, muted earth tones, golden rim light, armored angel with sword
```

**Example (artist name as trigger, for ComfyUI):**

```
painting by Greg Rutkowski, fantasy digital art, atmospheric lighting, painterly rendering, muted palette, golden highlights, lone knight on cliff
```

Rules:

- **25–45 words** max; same trigger on every image
- Emphasize medium, brushwork, atmosphere, palette — not plot
- Avoid “This image depicts…”, object inventories, camera jargon
- Use the **same trigger at inference** as in training captions

Caption with vLLM/Gemma (`bulk_caption_generic.py` in `~/ai-workspace/utils/`): set `--max-tokens 96`, sync `.txt` files into `dataset/`, then re-cache TE outputs only.

## Training

```bash
./train_krea2_lora.sh
```

**Steps per epoch** = `(num_images × num_repeats) / batch_size`.

With 153 images, `num_repeats = 4`, `batch_size = 1` → **612 steps/epoch**.

**Expected speed:** ~15–18 s/step with `compile` + fp8 on GB10 (first epoch slower while kernels compile). `torch.compile` graph-break warnings on `Tensor.item()` in attention are **safe to ignore**.

**Do not use for training:**

- `--sage_attn` / SageAttention3 (blocked by musubi-tuner for training)
- `discrete_flow_shift` with `krea2_shift` (no effect on timestep sampling)

**Optional speed / memory notes:**

- `compile = true` — recommended on GB10
- `split_attn = false` — fine at 1024 single bucket
- Keep `batch_size = 1`; use `num_repeats` to increase exposure per epoch

## Memory / OOM (DGX Spark)

Original OOM: full bf16 DiT + multi-res up to 1536px + no gradient checkpointing + optional Turbo sampling during train.

Fixes applied in config:

1. `gradient_checkpointing = true`
2. `fp8_base = true` + `fp8_scaled = true` (both required for K2)
3. Single 1024 bucket (removed 1536 tier)
4. Sampling during training disabled (`text_encoder`, `turbo_dit`, `sample_prompts` commented out)
5. Launcher env: `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`, `MALLOC_ARENA_MAX=2`

If still OOM: drop `compile`, lower `max_train_epochs` for a test run, or add `blocks_to_swap` + `block_swap_h2d_only` (cannot combine with `turbo_dit` sampling).

## Checkpoints and resume

Two artifacts are written each epoch:

| Artifact | Path | Purpose |
|----------|------|---------|
| LoRA weights | `output/{name}-00000N.safetensors` | Inference, ComfyUI |
| Resumable state | `output/{name}-00000N-state/` | Optimizer, scheduler, RNG |
| Final (train end) | `output/{name}.safetensors`, `output/{name}-state/` | Last epoch only |

`save_last_n_epochs_state = 2` keeps only the two newest `-state/` dirs.

### How to stop

Wait for an epoch to finish (log shows `saving checkpoint` and `saving state at epoch N`), then Ctrl+C. Mid-epoch stop → resume from the **previous** epoch’s `-state` dir.

### How to resume

`max_train_epochs` on resume = **additional epochs in this run**, not cumulative total.

Example: finished 8 epochs, want 4 more → set `max_train_epochs = 4` and:

```toml
resume = "output/greg_rutkowski_v4_krea2-state"
```

Look for startup log:

```
resume training from local state: output/greg_rutkowski_v4_krea2-state
Loading states from ...
```

**The UI will still show `epoch 1/N`** — that is normal (musubi-tuner does not restore the display epoch counter). Weights and optimizer state are still loaded.

### Weights-only continue (no optimizer resume)

```toml
network_weights = "output/greg_rutkowski_v4_krea2-000007.safetensors"
max_train_epochs = 4
# no resume line
```

## TensorBoard

Requires `pip install tensorboard`. Enabled in `configs/krea2_train.toml`:

```toml
logging_dir = "logs"
log_with = "tensorboard"
log_prefix = "greg_rutkowski_"
```

```bash
tensorboard --logdir logs --bind_all
```

Open http://localhost:6006. Metrics: `loss/current`, `loss/average`, `loss/epoch`, `lr/unet`.

Logs are **not** in `output/` — only checkpoints go there.

## Inference

### musubi-tuner CLI (Turbo)

```bash
python src/musubi_tuner/krea2_generate_image.py \
  "painting by Greg Rutkowski, armored angel in stormy clouds" \
  --dit models/turbo.safetensors \
  --vae models/qwen_image_vae.safetensors \
  --text_encoder models/qwen3vl_4b_bf16.safetensors \
  --lora_weight output/greg_rutkowski_v4_krea2-000007.safetensors \
  --lora_multiplier 1.0 \
  --steps 8 --guidance_scale 1 \
  --width 1024 --height 1024 \
  --attn_mode torch \
  --save_path output/samples
```

Use the **same trigger phrasing** as in training captions. Try `--lora_multiplier` 0.8–1.2. Compare epoch checkpoints (`-000004`, `-000007`, etc.); the final `output/{name}.safetensors` may be from a **resumed** run with fewer epochs than you expect.

### ComfyUI

Train on RAW, infer on **Krea 2 Turbo**, CFG off, ~8 steps. Match training trigger in prompts.

## Style training checklist

- [ ] Short captions, fixed trigger, 25–45 words
- [ ] Re-cache TE outputs after caption changes
- [ ] Single 1024 bucket, `num_repeats = 4`
- [ ] 8–12 epochs; inspect loss curve in TensorBoard
- [ ] Evaluate multiple epoch checkpoints on Turbo (not only final `.safetensors`)
- [ ] If style is weak: shorten captions further, try `learning_rate = 5e-5`, or increase epochs
